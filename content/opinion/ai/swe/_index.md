## 一、文档驱动（SDD）与工程中心法则 {#sdd-and-dogma}

### 什么是“软件 3.0”与“写意编程”的新协作范式？ {#software-3-and-xieyi}

正如 Karpathy 所揭示，自然语言已继确定性代码（1.0）与神经网络权重（2.0）之后跃升为“软件 3.0”接口，全球存量软件都将被重写。我主张把 Vibe Coding 译为中国画里的“写意编程”而非跑偏的“氛围编程”：手敲代码字斟句酌如“工笔”，传达高维意图、重神似轻形似正合“写意”，“写”字更一语双关。在攻克长尾可靠性之前，最务实的形态是 Cursor 式“钢铁侠战衣”——靠红绿 Diff 调用人类“视觉 GPU”加速核验，并用“自主性滑块”小步快跑。

### 不逐行手审代码时，Token 预算与验收底线立在哪？ {#qa-token-budget}

糊出 80 分功能半成品既快又不费多少 Token，但要把基础软件推向敢上生产的 95 分，70%～80% 的算力预算都必须砸进最后 20 分的暴力测试、对抗找茬与架构纠偏上。单测与集成测试可交给异构模型互审，唯独验收签字等于拿个人信誉背书，绝不能外包给 AI：我的硬抓手是强制同步交付代码级标准的 `Get Started` 手册，亲自照着手册跑通全流程。代码只记 What 与 How，归档每次权衡缘由（Why）的 `Session Log` 与伴生文档站才是真正的灵魂资产。

### 当模型返回概率而非定论，软件逻辑将如何动态结晶？ {#crystallization-and-cost-matrix}

未来的软件逻辑将沿“三层梯度”动态结晶：陌生任务先由前沿大模型生成一次性探索脚本，跑顺后收敛为几个关键判断点交给百毫秒级“无嘴模型”，摸透后再固化为确定性函数。更深刻的是，判断层是体系结构中首个故意向上传递不确定性的层级——它把客观概率原样交给唯一清楚出错赔多少钱的应用层，让控制流重回代码的 `if` 并由代价矩阵算贝叶斯阈值：若漏报故障赔 50、误报赔 5，最优阈值绝非拍脑袋的 `0.9`，而是 `0.09`。

百万行跨语言移植（Vibe Porting）只适合原团队自译：Bun 烧 16.5 万美元译百万行仍踩 19 个回归，能投产全靠测试、流量与兜底责任人在原地；外部重写 PostgreSQL 搬不走验证闭环与责任主体。对成熟底座最高价值的贡献是派 AI 考古邮件列表，把老黑客的默会教训固化为失败用例（Failing Test）；而在 MinIO 停摆这类真空地带，一人公司凭 7 个顶级订阅花一月即可将分支 Silo 推成超 2,200 Star、52 万拉取的社区标准。

## 二、Agent OS、上下文架构与记忆真相 {#agent-os-and-context}

### 为什么独立记忆框架是死路，“记忆是环境的补集”？ {#memory-complement-of-env}

### 如何低成本根治 Coding Agent 的跨会话失忆？ {#cross-session-wiki}

Coding Agent 是“隔夜失忆的天才工程师”，放任不管既会到处乱写自相矛盾的散装笔记，又会重踩早已否决的旧坑；但让单个野生 Agent 离线“做梦”整理知识库动辄烧掉上亿 Token，账面根本回不了本。最划算的解法是双层结构化知识沉淀：底层用数据库与编年体日志完整托底原始事实与思考轨迹，顶层通过 SDD 预维护互相链接的 Markdown Wiki 并在 `AGENTS.md` 中提炼决策索引供所有会话复用——实测准确率跃升至 61%，单题还能省下约 2 万 Token。

### 为何顶级工具弃用向量库回归 grep，检索怎么选？ {#grep-over-rag}

Claude Code 弃用早期本地向量库回归目录加 `grep`，是因为固定切片向量管线只能提前盲猜一次相关性且背负索引同步税；而把目录写进 `AGENTS.md` 交给 Agent 按需翻阅，“能边找边改主意”，Pigsty 文档站凭此零向量方案扛住了月均上亿 PV。检索架构选型应看资料形态与延迟预算：量小直塞上下文；自带目录引用的代码库与手册交给 Agent 自主搜；唯有十万份杂乱合同邮件，才需建“全文检索抓型号错误码 + 向量补口语同义词 + 元数据权限过滤”的混合栈。

### 为何单对话框小秘书遇大工程就拉胯，群聊才是正解？ {#group-chat-context-container}
