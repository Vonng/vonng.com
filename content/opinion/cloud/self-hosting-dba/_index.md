云厂商鼓吹“淘汰 DBA”只是为了垄断稀缺运维能力按核收租。借现代 NVMe 硬件红利砍掉分布式伪复杂度，用开源数据库管控配合边缘网络，企业完全能以十分之一成本实现工业化自建。

### 为何开发者才是真用户，讨好传统 DBA 必死？ {#developers-as-true-db-users}

客座作者瑞典马工打了个精准比方：大巴司机只是随车配套组件，乘客才是真用户；同理，传统专职 DBA 本质是强势原厂转嫁甲方付薪的“前置碳基 SQL 优化器”，写业务代码的开发者才是唯一真用户。老牌 DBA 靠甲骨文晦涩细节立身，换库等于废掉九成武功，天然抗拒迁移；新数据库唯有绕开 DBA 阻力、直接赋能开发者生产力才能活下来。

用四千人研发靠 Terraform 与云托管跑通“零专职 DBA”来鼓吹裁撤 DBA，混淆了自动化红利与制衡边界：系统“安全性”与“活性”天然互斥，研发追发版活性，DBA 必须替稳定性踩刹车——核心库崩一次足以让数月心血归零。况且闭口不谈 64C RDS 月租 18 万元而吹嘘“半小时建库”纯属慷公司之慨；开源 Pigsty 配 Terraform 同样十几分钟交付，还能省下八九成云税。

### 微服务如何稀释数据治理，专职专家核心价值在哪？ {#dba-fighting-dev-entropy}

开源免授权、云 RDS 包办表层运维及微服务拆分风潮，诱导企业把模式治理甩给不擅此道的业务研发。殊不知最大算力黑洞正是“研发乱用数据库”——糟糕建模与烂 SQL 足以造成数个数量级性能坍塌，填坑账单远超专家年薪。云端所谓“AI 自治”连及格监控都不算，优秀 DBA 的灵魂正是守住事实源底线并对抗系统熵增。

### 专职 DBA 是放大风险，还是更能收敛攻击面？ {#dba-security-vs-cloud-privilege}

微盟与百度等删库惨案均由普通研发运维肇事，恰恰印证缺称职 DBA 把关才会沦为“人人可删库”。合格 DBA 如总账会计，靠高危收敛、双人互备与冷备删除权分离筑起铁桶制衡；全盘上云反而无法审计云端特权窥探或批量脚本误伤。至于因不懂关系建模去捧 10 毫秒高延迟的天价 NoSQL 更是做梦——百万 IOPS NVMe 配千亿行单表 PG 早已抹平分库痛点。

### 云数据库靠五十倍杠杆抢谁饭碗，埋下了什么隐忧？ {#rds-leverage-and-junior-dba}

开源内核免费后，行业真正稀缺的是经大故障淬炼的顶级驾驭能力，国内能搭出超越 RDS 水准的 PG 专家不过数十人。云厂商遂转向垄断运维能力：靠 70 分闭源管控预制菜加共享专家池（用 2% 专家时间兜底低频疑难，跑出 50 倍人力乘数），精准碾压了初中级 DBA 三五十分的土法自建；但中小企业练兵场被抽干后，整个行业正面临断代风险。

复杂度守恒决定了自动化代码只能消化约七成例行杂活，疑难兜底与架构治理永远需要内行。这正触发双向分化：组织内百名初级运维浓缩为十名高阶数据库可靠性工程师（DRE）；产业外换皮伪内核走向消亡，“廉价硬件 + 开源内核 + 开源管控 + 独立专家兜底”（连 DHH 下云也买 Percona 兜底）才是终局，开源配 AI 百倍杠杆终将终结云垄断。

## 二、拒绝复杂度自慰：硬件红利与极简架构 {#simplicity-and-hardware-dividend}

### 软件不像造大炮，单人为何能摸透从内核到账单？ {#software-not-krupp}

克虏伯工人看不见整门大炮源于重工业物理硬约束；大厂螺丝钉拿分工替视野残缺辩护，却忘了软件毫无这层物理枷锁。如 Fred Brooks 所言，现代基建九成繁琐皆是人为叠床架屋的“偶然复杂度”。只要砍掉自嗨中间层，单人完全能从内核参数、SQL 执行计划、高可用切换一路摸透到硬件网络账单的每一分钱。

- [大厂出来的人，为什么这么废 · 软件不是克虏伯](/cloud/waste/#软件不是克虏伯)

### 硬件红利为何让分库分表与分布式数据库成了鸡肋？ {#hardware-kills-distributed-db}

多核 CPU 与企业级 NVMe 的性能跃迁早已让“可伸缩性焦虑”沦为历史伪问题：单台现代高配服务器足以跑下整个 Twitter 负载，淘宝五年 82 亿条购物记录压缩后仅 600GB，单机 PostgreSQL 或 DuckDB 即可通吃 99.99% 企业终生负载。分布式数据库本质是“以质换量”，单机远未触顶却去阉割事务、背负跨网延迟与运维重担，纯属刻舟求剑。

- [重新拿回计算机硬件的红利 · 分布式不再受待见](/cloud/bonus/#分布式不再受待见)

### 多租户为何是复杂之源，软件正摆回单租户买断吗？ {#single-tenant-vs-public-rental}

37signals 联创 DHH 一针见血：单一组织内部系统几乎压不垮一台现代服务器，Web 服务二十年来堆砌的沉重架构全是为了应付数百万客户混跑的“多租户”。其 ONCE 项目将月租 SaaS 还原为买断自托管在单机与 SQLite 上的单租户软件，根除了规模负担。所谓公有云实为“公租云”，非强网络效应的工具软件正加速摆回用户拥有产权的私属时代。

- [单租户时代：SaaS范式转移 · 多租户是 Web 服务的复杂之源](/cloud/single-tenant-saas/#多租户是-web-服务的复杂之源)
- [单租户时代：SaaS范式转移 · 隔壁老冯评论](/cloud/single-tenant-saas/#隔壁老冯评论)

### 脱离公有云与容器编排，枯燥单库栈能扛住四个九吗？ {#boring-stack-four-nines}

DHH 晒出的 37signals 下云战绩给出了铁证：七大应用全年可用性超 99.99%，Basecamp 2 连续两年零停机，靠的全是 Linux、Docker、MySQL 与 Redis 等枯燥组件，坚决抵制照搬巨头屠龙术的“智力自慰”。我在探探早中期的实战同样如此：纯 Go 配单一 PostgreSQL 稳扛数百万日活、250 万 TPS 与 200TB 数据，逼近千万日活才按需拆分。

### 国内域名备案会锁死解析吗，催缴小钱蠢在了哪？ {#dns-lockin-illusion-broken}
