云计算不仅是一笔算力租赁的经济账，更是一场围绕基础设施控制权与软件自由的政治账。当公有云寡头异化为征收垄断租金的“数字封建领主”，当 AI 自动化挖洞将多租户云平台打成筛子，当超级平台滥用生态白名单与终端特权反噬普通用户，交出数据主权的代价早已从“多花冤枉钱”升级为“丧失生存底线”。本篇围绕数据主权与本地优先、SaaS 断供开关、AI 时代云安全防线、超级平台阴影与大厂开源博弈，拆解如何在巨头高墙之外夺回属于自己的数字家园。

## 一、数字封建制、数据主权宣言与本地优先 {#data-sovereignty-and-local-first}

### 为什么说寡头公有云不是商业租赁，而是“数字封建制”？ {#digital-feudalism}

中世纪领主无需皮鞭锁链，因为农奴每次耕作都在肥沃领主土地并加深依附。寡头公有云原样复刻了这套结构暴力：先如烟草商般用免费赠金与无感接入哄诱团队交出架构，待私有接口缠绕、自建手艺退化后便收紧绞索，进入的自由从未对等于离开的自由。更致命的是在 AI 时代，托管核心数据意味着你不再是客户而是矿藏——你无偿贡献的业务轨迹被提炼成模型能力，既加价卖回给你，又同步卖给竞争对手压低你的利润；昔日打破传统 IT 垄断的屠龙者已彻底沦为恶龙。

- [数据主权宣言 · 二](/cloud/data-sovereignty-manifesto/#二)：剖析公有云私有接口、迁移壁垒与用户自建能力萎缩如何精确复刻中世纪庄园依附关系。
- [数据主权宣言 · 三](/cloud/data-sovereignty-manifesto/#三)：拆解云厂商如烟草业般用初期赠金与便利培养重度依赖、待戒断成本高不可攀后涨价收割的成瘾机制。
- [数据主权宣言 · 四](/cloud/data-sovereignty-manifesto/#四)：揭示 AI 时代数据托管者沦为大模型免费燃料矿藏、业务模式被提炼后反向赋能竞争对手的二阶伤害。
- [云计算反叛军 · 问题](/cloud/cloud-rebels/#问题)：引述 Ubicloud 宣言指出三大公有云已从打破传统 IT 垄断的勇者异化为靠闭源黑盒征收暴利保护费的恶龙。

### 为何软件自由头号威胁已从闭源变成云，出路在本地优先？ {#cloud-vs-local-first}

开源曾击碎 Oracle 万元核月授权费垄断，却被云巨头零成本“吞噬”：把 IDC 自建仅 19～26 元/核·月的硬件算力套壳卖出二三百乃至上千元的十余倍暴利，并刻意混淆池化云硬件（IaaS）与黑箱云软件（PaaS/SaaS）。正如 Martin Kleppmann 所警示，当今主矛盾已从“开源 vs 闭源”转向“本地 vs 云”——本地闭源软件在厂商倒闭或封号时仍可续跑迁移，云软件却握有单向生杀大权。唯有回归 K8s、MinIO/Ceph 与 Pigsty 等“在任意自有环境跑出云体验”的本地优先软件，才能兼得便利与主权。

- [范式转移：从云到本地优先 · 二律背反](/cloud/paradigm/#二律背反)：算清 IDC 自建与云 RDS 十余倍核月差价，揭穿云厂商混淆池化硬件（IaaS）与黑箱云软件（PaaS/SaaS）的套利本质。
- [范式转移：从云到本地优先 · 矛盾嬗变](/cloud/paradigm/#矛盾嬗变)：结合 Kleppmann 论断对比本地闭源软件与服务端托管云软件，论证云软件对用户数据与能力的单向剥夺风险。
- [范式转移：从云到本地优先 · 本地优先](/cloud/paradigm/#本地优先)：正本清源 Cloud Native 的解放内核，展示 K8s、Ceph 与 Pigsty 如何在自有硬件上交付云端运维体验。

### 空谈隐私合规无济于事，真正的数据自主权靠什么落地？ {#data-autonomy-run-right}

没有工程工具支撑的权利声明只是一纸空文。完整的数据自主权（Data Autonomy）除知情权、撤回控制权与常规迁移权外，决定性的分水岭是第四项——用免费可靠的开源工具向所有人交付在自有或可控硬件上独立跑起数据底座的“运行权”。正如 DHH 以“主权云（Sovereign Cloud）”重塑下云话语：容器、负载均衡与可观测性等九成云原生技能在自有硬件上完全通用，唯一省掉的是盯防账单爆炸的 FinOps。终结数字封建制不靠乞求宽厚租约，而靠开源自建掀起“数字土地改革”，让锁定模式自行坍塌。

- [数据主权宣言 · 七](/cloud/data-sovereignty-manifesto/#七)：定义知情权、控制权、迁移权与决定性的自有硬件“运行权”，阐明开源数据库与运维工具如何将权利变为现实能力。
- [数据主权宣言 · 九](/cloud/data-sovereignty-manifesto/#九)：以土地改革类比开源自建运动，论证唯有培育独立运行的“数字自耕农”才能淘汰依赖锁定的封建激励结构。
- [下云奥德赛：该放弃云计算了吗？ · 05-03 从云遣返到主权云！](/cloud/odyssey/#05-03-从云遣返到主权云)：引述 DHH“主权云”宣言，点明自有与租赁才是根本分野，反击“你将一无所有并乐在其中”的寡头洗脑。

### 预算买不起物理机房，中小团队如何撕掉卖身契赎回主权？ {#cyber-knight-pg-s3}

计算、带宽与 Token 皆是大宗商品，真正制造锁定的唯有承载沉重数据引力的数据库与对象存储。硬件涨价最多拦住你当自有机房的“赛博地主”，绝拦不住你从签死专有 PaaS 的“赛博农奴”赎身为跨云比价的“赛博骑士”：拒绝一切私有接口，将状态层收敛至既有云托管又有开源实现的 PostgreSQL 与 S3 标准协议。在此之上，无论是像 Ubicloud 在 Hetzner 平价裸机上架设开源管控层降本 3～10 倍，还是用开源 RDS 替代方案 Pigsty 一键拉起企业级 PG，都能零物理机投入夺回主权。

- [下云的人已经赚麻了 · 六、锁你的不是服务器，是数据](/cloud/cloud-exit-2026/#六锁你的不是服务器是数据)：指出有状态 PaaS 才是锁定命门，提出将状态依赖收敛至 PostgreSQL 与 S3 标准协议以实现零改码进退自如。
- [下云的人已经赚麻了 · 八、赛博封建等级表](/cloud/cloud-exit-2026/#八赛博封建等级表)：划分赛博农奴、赛博骑士与赛博地主三级主权光谱，给出只租裸 IaaS 加自建开源 PaaS 的零硬件赎身路线。
- [云计算反叛军 · 解决方案](/cloud/cloud-rebels/#解决方案)：拆解 Ubicloud 在平价裸金属服务器上运行开源 IaaS 与托管 PG、让 GitHub Actions 降本 10 倍的实测方案。
- [云计算反叛军 · 我们的请求](/cloud/cloud-rebels/#我们的请求)：论证有状态数据库（尤其是开源 PostgreSQL 替代云 RDS）是掀翻公有云暴利饭桌的决战高地。

### 跨国合规与高可用真能靠云兜底吗？为何反成全局单点？ {#cloud-centralization-and-gdpr}

迷信跨国公有云兜底安全与合规纯属错觉。正如 DHH 所言，容器化让云上云下的补丁维护毫无二致；而在隐私合规上，AWS、Azure 与 Google Cloud 均受美国法律管辖，无论机房设在何处美方均有权强制调取数据，严守 GDPR 恰恰必须在当地机房运行自有硬件。更致命的是，当政务、金融与民生应用高度集中于少数云寡头，去中心化的互联网反而长出了史无前例的全局单点——一旦境内单一控制面失误瞬间卡住全球区域的脖子，海外客户必将因数据主权红线加速迁离。

- [半年下云省千万，DHH下云FAQ](/cloud/cloud-exit-faq/)：结合 DHH 答疑戳破“上云更安全合规”的神话，指出规避美国跨境调取法令与满足严格 GDPR 必须依靠本地自有硬件。
- [我们能从阿里云全球故障中学到什么? · 评论与观点？](/cloud/aliyun/#评论与观点)：复盘阿里云全球级宕机，揭示高度中心化的云寡头如何异化为全局单点故障源并触碰跨国数据主权合规红线。

## 二、SaaS 生杀开关、供应链控制权与删库幻觉 {#saas-kill-switch-and-control}

### 合同写明数据归你，为何 SaaS 停服时仍会一夜清零？ {#saas-kill-switch}

条款写满“客户拥有数据”也抵不过丧失技术控制权：Slack 关停大中华区时仅给单一 Owner 发邮件，且将自助导出绑死在后台——到期锁后台即断导出通道，常规档位连导出私聊都得看平台审批。从制裁封号、印度封锁 Supabase 到 Slack 因合规算不过账清退区域用户，叠加 CLOUD Act 管辖，SaaS 无需恶意就能因外部 ROI 掐断你的业务。搬进飞书、钉钉只是换房东交开关；唯有坚持“每月离线导出+恢复演练”，或一小时拉起开源栈（PG + Mattermost/GitLab/Keycloak），才能拿回三层主权。

- [你的 SaaS，别人的开关 · 三、你的数据，你能拿走吗？](/cloud/slack-exit/#三你的数据你能拿走吗)：剖析 Slack 单点通知机制、后台锁死即断绝自助导出及私有记录审批限制如何令团队一夜痛失多年组织记忆。
- [你的 SaaS，别人的开关 · 五、这不是道德问题，是结构问题](/cloud/slack-exit/#五这不是道德问题是结构问题)：串联 GitHub 封号、Supabase 遭封锁与 Slack 区域清退叠加 CLOUD Act 管辖风险，揭示把生产力建在别人开关上的结构性脆弱。
- [你的 SaaS，别人的开关 · 七、数据主权是一个工程问题](/cloud/slack-exit/#七数据主权是一个工程问题)：指出换用国内巨头 SaaS 仍是交出开关，给出定期离线导出恢复演练与基于成熟开源套件自建的两级工程防线。

### 宣称不可恢复的云数据竟能复活，网盘串号暴露了什么？ {#cloud-ghost-retention-and-nas}

比误删更恐怖的是云端数据生命周期的黑箱失控。某十万用户软件因腾讯云欠费 2 元释放，官方文档明写停服七天释放后“清除且不可恢复”，舆情发酵后却奇迹找回——说明所谓销毁多半只是软标记或冷归档，行使“被遗忘权”时数据仍躺在后台任人接触。再看阿里云盘曝出新建文件夹即可刷出他人私密照片的灾难级漏洞，且事发时违背“机密性高于可用性”铁律拒不学 Klarna 立即断服止血：公有云网盘顶多配做影视下载中转站，个人私密影像与核心资产必须锁进自家本地 NAS。

- [10万用户的软件，因腾讯云欠费2元灰飞烟灭？ · 不可恢复的恢复了？](/cloud/tencent-2yuan/#不可恢复的恢复了)：追问文档承诺“彻底清除不可恢复”的欠费释放实例在舆情后复活的真相，警示云后台未授权留存与窥探隐患。
- [阿里云盘灾难级BUG：能看别人照片？](/cloud/aliyun-drive-bug/)：复盘阿里云盘跨账号看他人私密照片漏洞及未及时熔断止血的处置失当，论证个人核心隐私资产必须回归本地 NAS。

### 从全球蓝屏星期五看，甲方为何绝不能让渡升级控制权？ {#bsod-friday-upgrade-sovereignty}

CrowdStrike“蓝屏星期五”撕开了盲信供应链的代价：乙方安全团队单维度追求“最快拦截”，甚至傲慢抱持“蓝屏死机也好过被黑”；但对医院、航司与银行而言，规则库晚几小时灰度上线天塌不下来，全球同步蓝屏却是灭顶之灾。核心系统面对任何更新都须死守“Trust, But Verify”，分批验证与上线时机的拍板权必须留在甲方手里，不给灰度选项的乙方理应一票否决。真正的自主可控是践行本地优先：如 Pigsty 打包全量离线依赖快照，断网可永续运行，升级节奏全由自己做主。

- [蓝屏星期五：甲乙双方都是草台班子](/cloud/bsod-friday/)：剖析安全厂商强制空中升级与甲方放弃灰度把关的双重失职，提出断网可独立运行、升级由己做主的本地优先交付准则。

### AI 包揽九成编码，为何明星项目仍连犯打包团灭错？ {#ai-code-human-release-gate}

OpenClaw 发 `v2026.3.22` 时漏打整个 `dist/control-ui/` 前端、自救 `scripts/` 与 `@openclaw/whatsapp` 依赖，致全球 npm 升级 503 团灭——连续三月栽在打包链路，只因 CI 缺了四行命令的真装验证。Pigsty v4.x 同样超 99% 代码由 AI 编写，AI 写码没问题，但不会替人立规矩：像 ETCD `3.6.8` 升 `3.6.9` 悄悄给探活接口加认证这种暗坑，光看 Diff 防不住，唯有干净环境冒烟实测、遇坑锁版回滚才配跑生产。

- [OpenClaw 小龙虾翻车：不测就发的后果 · 二、不是第一次了](/cloud/openclaw-drama/#二不是第一次了)：梳理 OpenClaw 连续三个月因打包漏文件导致全球升级瘫痪的事故链，揭示狂飙突进背后缺失最基本的安装后验证。
- [OpenClaw 小龙虾翻车：不测就发的后果 · 三、AI 写代码，但不管发布](/cloud/openclaw-drama/#三ai-写代码但不管发布)：对比 Pigsty 交付铁律与 ETCD 小版本暗坑案例，阐明 AI 时代人类维护者最不可外包的是端到端真装实测的发布门禁。

### 为什么简短通用的 S3 桶名既是账单炸弹又是泄密黑洞？ {#s3-bucket-name-trap}

对象存储全局唯一命名空间是一片黑暗森林。研究者 Maciej Pocwierz 排查天价未授权请求账单时，试着将取了常见词的 S3 桶临时设为“公共写入”，不到 30 秒便收到外部错配系统自动投送的超 10 GB 真实企业备份！这记双重警钟要求工程团队严守两条铁律：创建存储桶严禁用简短常见词汇，必须拼接高熵随机后缀以防撞名破财与定向爆破；同时在代码中发起大规模 S3 请求时务必显式绑定 Region，规避默认路由至 `us-east-1` 带来的高额跨区重定向账单。

- [云上黑暗森林：打爆云账单，只需要S3桶名 · 安全层面的问题](/cloud/s3-scam/#安全层面的问题)：复盘开启公共写入 30 秒内意外截获超 10 GB 外部企业备份的惊魂实验，给出桶名随机后缀与显式指定区域的防御铁律。

## 三、AI 攻防海啸、被打成筛子的云与数据裸奔 {#ai-vuln-tsunami-and-data-leaks}

从 PHP2Shell、12 年 GitLab 满分 RCE、`CVE-2026-99999` 逃逸到 LiteLLM 投毒，一周内 Zeabur 关停、TiDB Cloud 泄 10.6 TB、IDCF 五百企停摆——祖传代码正遭 AI 流水线挖洞洗礼。趴在 EOL 的 CentOS 7.9 或迷信“最后免费版不会坏”等于等死：MinIO 断供后社区版 Silo 半年修了 20 多个漏洞，黑客把公开补丁喂给大模型做 Patch Diffing，几分钟就能产 Exploit 扫街。活路唯有两条：保持平滑升级且有人持续发补丁，或拔掉公网线。

- [当互联网真被打成筛子 · 停更软件的宿命：连网即裸奔](/cloud/net-attack/#停更软件的宿命连网即裸奔)：以 Silo 分支半年修复逾 20 个漏洞为例，拆解大模型 Patch Diffing 如何在几分钟内将断更联网软件变成公开后门。
